# Обложка скоупа — разбор 07.09.2026

Короткая карта сессии: что было сломано, что снято, что добавлено и как это проверять. Нужна,
чтобы через два дня не поднимать всё заново.

## 1. Корень: судья молчал, а код звал это отказом

28.08 роль выбора обложки переехала на `claude-sonnet-5` (коммит `0fba26b`, «роли без мышления — на
Sonnet 5»). Для Sonnet 4.6 это было верно, для 5 — нет: **она думает по умолчанию**. У вызова стоял
`max_tokens=40`, весь бюджет уходил в блок `thinking`, и текста в ответе не оставалось:

```
stop_reason: max_tokens
blocks:      [('thinking', '')]      ← текста нет
```

Разбор искал цифру в пустой строке, получал 0 и писал в лог «vision не выбрал подходящую по смыслу
картинку». Семь дней **техническая поломка докладывалась как вкусовое решение**. Журнал обложек
`data/scope_cover_log.jsonl` за это время не создан ни разу: пять скоупов подряд ушли голым текстом
(28.08, 31.08, 02.09, 04.09, 07.09).

Предохранитель `llm._thinking_for`, заведённый тем же коммитом, не помог по конструкции: он чинит
вызовы через `core/llm.py`, а выбор обложки ходит в Anthropic напрямую — ему нужны картинки.

**Починено:** мышление гасится явно (`thinking={"type": "disabled"}`), бюджет ответа 120, повтор без
параметра на `BadRequestError`/`TypeError` (модель или старый SDK). Пустой ответ теперь ERROR в логе
и «сбой, а не отказ» в панели.

## 2. Второй слой: пул протух, пока поломка была не видна

С 26.08 по 31.08 каждый отдельный промах чинился надстройкой, и каждая уводила пул дальше от того,
чем были все 23 принятые обложки — **шапки материала от редакции издания**.

| Что добавляли | Чем обернулось |
|---|---|
| кадры из ТЕЛА статьи (26.08) | аватарки колумнистов, инлайн-инфографика, превью соседних новостей |
| поиск по объекту ПЕРВЫМ маршрутом (31.08) | «фото фирмы вообще» вместо кадра события (вход в отделение DBS с китайской вывеской) |

| ранжирование «по ступеням» в промпте | судья взвешивал всё сразу и брал то, что ярче |

**Снято всё перечисленное.** Порядок вернулся к доперелому: сперва шапки страниц повода, поиск по
объекту — вторым (но всегда, как альтернатива рисунку: полотно с официального сайта). Из добавленного
по сути одно — вопрос судье разбит на узкие круги.

## 3. Как устроен подбор сейчас

**Пул** (`core/scope_writer._attach_media`):
1. Шапки страниц повода (`og:image`). Страница закрыта (coindesk 429, theblock 403) → кадр статьи
   берётся из RSS этого же издания (`fetch.feed_image_url`, 9 лент).
2. Поиск по объекту повода — 2 кадра как альтернатива, или полный набор, если шапок меньше двух.
3. Фильтры, все детерминированные: мусор по имени файла (мерч, скриншоты, квитанции, аватарки) →
   мультяшные шапки изданий-маскотов → кадры из тела статей → не-горизонталь (порог 1.45) →
   мелкие кадры при наличии кадров от 1000px.

**Выбор** (`_vision_pick`) — последовательность узких вопросов, каждый про ОДИН класс:
1. снятая камерой фотография по поводу;
2. фирменное полотно бренда;
3. редакционная иллюстрация про САМО событие;
4. принудительный выбор наименее плохого из невредных (стоп-лист `_COVER_HARM`).

Признание судьи в ярлыке («не по теме», «это ИИ-генерация») = ноль на любом круге. Номер без ярлыка
при оборванном формате = не выбор.

**Правила** живут в памяти: `memory/scope_cover_manual.md` (владелец правит руками). §5 — закрытый
стоп-лист, §6 — «бери первое из ступеней», ступень 0 — «снято камерой бьёт нарисованное».

## 3.5 Что из этого — рабочее ядро, а что новое

Владелец: «возьми рабочее решение + пользу от того что есть». Разложено явно, чтобы через два дня
не спорить заново, что тут наследие, а что надстройка.

**Рабочее ядро (как было до 26.08, восстановлено):**
- пул = ШАПКИ СТАТЕЙ изданий про это событие, тир-1 первыми;
- писателю велено давать 3-4 статьи РАЗНЫХ изданий (июльская инструкция «сначала официальный сайт
  компании» перевёрнута: она и уводила обложку в «фирму вообще»);
- никакого выскребания тела статей и никакого «поиска по объекту» впереди статей.

**Новое, оставленное потому, что чинит ядро или описывает его:**
| что | зачем оставлено |
|---|---|
| RSS-маршрут к тир-1 | возврат ПОТЕРЯННОГО источника: coindesk 429, theblock 403 — их художка выпадала молча |
| мышление судьи выключено, бюджет 120 | ремонт поломки 28.08, без него не работает ничего |
| фильтры (тело, маскоты, мерч, скриншоты, вертикаль, разрешение) | не изобретение, а описание того, чем и были 23 обложки; держат пул от повторного протухания |
| поиск по объекту вторым маршрутом | альтернатива рисунку там, где вся пресса рисует (дал полотна Solana и Robinhood) |
| журнал обложек | анти-повтор кадра и объекта |
| tools/probe_covers | замер вместо спора словами |

**Единственное настоящее добавление** — вопрос судье разбит на узкие круги вместо одного «годится?».
Старый один вопрос работал, потому что в пуле лежали только шапки тир-1 и выбирать было почти не из
чего. Пул сегодня шире (плюс поиск по объекту, плюс второй эшелон изданий) — значит нужен порядок,
иначе судья берёт то, что ярче.

**Про ИИ-картинку, с которой всё началось (26.08).** Генерация у скоупа в коде БЫЛА (снята `da16a40`),
но та картинка была НЕ наша — она приехала шапкой чужой статьи. Разбор пошёл за генерацией вместо
приёмки, и дальше три сессии чинились фильтры, пока настоящая поломка (судья молчал) оставалась
невидимой. Урок записан в §6.

## 4. Как проверять

```
python -m tools.probe_covers            # лист: что механизм подобрал сегодня
python -m tools.probe_covers published  # лист: 23 опубликованные обложки (эталон)
```

Два контактных листа в `data/cover_probe/`, вердикт глазами. Инструмент зовёт БОЕВУЮ `_attach_media`,
боевые файлы не трогает, стоит центы.

Замер 07.09 после правок — 5 сюжетов из 6 в стандарте (в начале дня 1 из 6). По сюжету про Coldcard
механизм выбрал ТУ ЖЕ обложку, которую владелец поставил руками посту #469.

## 5. Что осталось открытым

- **Сюжеты, где вся пресса рисует** (протоколы: Ethereum, Solana). По стоп-листу владельца рисунок
  «про отрасль» брать нельзя — значит иногда обложки не будет. Размен «пост без картинки против
  рисунка про отрасль» — решение владельца, не принято.
- **Скаут даёт мало ссылок на статьи.** В прогоне про Liquid их было четыре и кадр нашёлся, в
  прогоне про DBS — ни одной, и работала только страховка. Качество обложки прямо зависит от числа
  статей-первоисточников в брифе.
- **Заголовок.** Правило «читается без словаря» записано в `scope_manual §4` 07.09, но на живом
  прогоне ещё не проверялось.

## 6. Уроки, которые дороже кода

1. **Молчание модели ≠ её отказ.** Диагностику начинать с сырого ответа (`stop_reason`, типы блоков,
   usage), а не с чтения промпта. Один вызов за $0.03 опроверг разбор, построенный на чтении правил.
2. **Прямые вызовы Anthropic — слепая зона** для предохранителей `core/llm.py`.
3. **Проверять правку той же функцией, что работает в прогоне.** Два замера подряд собирали пул
   своим кодом мимо `_attach_media` и показывали картину до правок.
4. **Тест должен воспроизводить ВХОД, а не только код.** Кластеризация сюжетов по одному общему
   слову слепила нефть с закрытием Router — мерился не механизм, а группировка.
5. **Ранжирование в промпте не работает.** Порядок предпочтения обеспечивается либо составом пула,
   либо последовательностью узких вопросов.
