# 🧵 Автономная петля Threads — целевая схема (спец владельца 09.09.2026)

> Как это должно работать в итоге, его словами: «Я нажимаю одну кнопку и по графику получаю посты в
> ТГ + переработанные посты в Threads. Они сделаны заранее, за 4 часа до публикации — чтобы админ мог
> просмотреть, отредактировать, проверить. Если изменений не было — публикует по графику».
>
> Документ описывает ЦЕЛЬ и порядок сборки. Что уже стоит на месте — в [threads.md](threads.md) §11
> и [ARCHITECTURE.md](ARCHITECTURE.md) §4.1/§4.2.

## 1. Полный цикл одного дня

```
16:00−4ч   автопилот гонит ТГ-формат (флагман Вт/Чт | скоуп Пн/Ср/Пт)
           → пост + обложка ложатся в ОТЛОЖКУ боевого канала
           → владельцу уведомление на мейн
           → владелец правит ПРЯМО В ОТЛОЖКЕ (ТГ опубликует ровно то, что там осталось)
16:00      Telegram публикует пост сам
16:00+     Threads-ветка берёт ВЫШЕДШИЙ пост (его текст = то, что реально вышло, с правками)
           → мини-скоуп (1 тред + та же обложка) | мини-флагман (1-4 треда, текст)
           → ревью-копии в ОТЛОЖКУ тестового Threads-канала на время публикации −4ч
           → владельцу уведомление на мейн
T−0        публикатор Threads ПЕРЕЧИТЫВАЕТ ревью-копию и публикует ТО, ЧТО ТАМ ЛЕЖИТ СЕЙЧАС
```

## 2. Три правила, на которых стоит вся схема

1. **Источник для Threads — ВЫШЕДШИЙ пост, не черновик.** Владелец правит ТГ-пост в отложке; если
   деривация пойдёт с черновика, в Threads уедет текст, который он уже вычеркнул. Журнал вышедших
   постов (`published_journal`) — единственный мост между пайплайнами.
2. **Отложка ревью-канала — это ПУЛЬТ, а не витрина.** Оставил как есть → уйдёт как есть. Поправил →
   уйдёт ЕГО версия, а не файл из памяти завода. Удалил сообщение → в Threads не уйдёт ничего.
   Никаких отдельных кнопок «подтвердить»: владелец уже живёт в нативной отложке.
3. **Правка = сигнал обучения, а не просто правка.** Каждое расхождение «наш текст ↔ то, что осталось
   в отложке» меряется в процентах (как в ТГ, `core/edit_delta`), помечает пост как «правленый» и
   копит класс правки. Повторяющийся класс → урок в свод СВОЕГО формата. Цель — чтобы правок
   становилось меньше, а не чтобы они просто фиксировались.

## 3. Что для этого нужно построить

| Шаг | Что | Зачем именно так |
|---|---|---|
| A | **Очередь Threads** `data/threads_queue.jsonl`: текст, формат, id ревью-сообщения, время публикации, статус | у Threads API НЕТ отложенной публикации (проверено: параметра времени не существует, вызов публикует немедленно) — время держим мы |
| B | **id ревью-сообщения** при постановке в отложку (`telegram_publish` уже знает сообщение; нужно вернуть его id наружу) | правку ищем ДЕТЕРМИНИРОВАННО: у отредактированного сообщения id тот же, у удалённого id исчезает. Сверять по совпадению слов — гадание |
| C | **Повторная проверка перед публикацией**: перечитать сообщение по id → нет его = отмена; текст изменился = публикуем ЕГО и метим `edited` | это и есть требование «публикуется отредактированный пост админа, а не из файлов памяти» |
| D | **Замер правки** (`edit_delta` для Threads) + запись в журнал переработок | «сделай, чтобы редактирования было минимально» — без числа этого не измерить |
| E | **Публикатор из очереди**: линт охвата → квота Meta → ЗАПИСЬ открывается на ОДИН вызов с причиной и закрывается | правило «аккаунт важнее данных» остаётся живым и в автономии |
| F | **Третий выключатель автопилота** `data/autopilot_on_threads` + своё время выхода | форматы независимы: ТГ может идти, Threads стоять, и наоборот |

## 4. Открытые вопросы (решает владелец)

- **Время выхода в Threads.** ТГ выходит в 16:00 Франкфурт. Threads — тот же день вечером? Следующее
  утро? От этого зависит, когда ставить ревью-копию (T−4ч) и когда гнать переработку.
- **Серия мини-флагмана.** Между тредами нужны часы (два подряд каннибализируют охват): резать до
  двух сильнейших в один день или растягивать серию на два-три дня, наезжая на следующие посты?
- **Право пропустить.** Может ли мини-скоуп сказать «здесь человеческого угла нет» и не выйти —
  или на площадке важнее ритм и выходим всегда?

## 5. Картинки

Мини-скоуп берёт обложку ТГ-поста (она уже отобрана и опубликована), мини-флагман идёт текстом —
решение владельца 09.09. ⚠️ Threads API принимает картинку **только публичной ссылкой**: локальный
файл ему не отдать. Значит к вехе E нужен URL первоисточника кадра — сейчас мы храним только путь к
скачанному файлу.
