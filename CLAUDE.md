# TG-Agents — контекст проекта для Claude Code

## Что это
Персональная мульти-агентная ИИ-команда (контент-завод) вокруг Telegram-канала
и бренда владельца. Полный чертёж — в docs/PLAN.md, читай его для полной картины.

## Контекст прошлых сессий
Важные обсуждения и инсайты прошлых разговоров — в `notes/` (gitignore, локально). **Claude: читай
`notes/` при старте**, чтобы быть в теме и не переспрашивать. Архитектурные решения продублированы в docs/PLAN.md.

## Архитектура (коротко)
- Агенты-специалисты с ролями: стратег, аналитик, адаптер, продюсер, ресёрчер, разработчик.
- Память — ОТДЕЛЬНЫЙ общий слой, не внутри агентов:
  - memory/brand.md — канон (tone of voice, аудитория, цели), меняется редко
  - memory/strategy.md — живое состояние, у фактов даты, новое перекрывает старое
  - memory/decisions.md — журнал решений, только дополняется, с датами
- Принцип «мозги vs руки»: LLM-логика дёшева, интеграции (коннекторы) — самое сложное.
- Ядро отделено от коннекторов: систему переносим и на другие продукты, не только Telegram.

## Текущий фокус (с 12.07.2026)
Проект — **контент-завод** вокруг Telegram-канала. Команда сведена к трём агентам на одном ядре:
**Скаут** (разведка тем/источников → бриф), **Криейтор** (пишет пост + обложку → `/schedule` в канал),
**Аналитик** (судит контент по метрикам канала). Ранние отдельные боты — личный ассистент и developer —
**удалены 12.07.2026** ради фокуса (восстановимо из истории git; публикация-«руки» `_publish_now` +
коннектор `telegram_publish` сохранены). Северная звезда: мульти-платформа (дособрать Threads, Фаза 2) +
замкнуть петлю **скоринг→генерация** (самообучение). Стек: Python + aiogram + Git. Порядок — в docs/PLAN.md.

## Структура репозитория
- core/        — общий «движок агента»: бот (aiogram) + личность + доступ к памяти; переиспользуется всеми
- agents/      — определения агентов (личность/промпт, конфиг, доступы): scout, creator, channel-analyst
- memory/      — общий слой: канон бренда (brand.md), стандарт поста, уроки, плейбук «что заходит», брифы/драфты (шина)
- connectors/  — «руки»: Telegram Bot API (интерфейс), Telegram Client API/MTProto (выгрузка постов + отложки), позже свой Threads-коннектор (офиц. API Meta: аналитика своих постов + публикация), календарь/таск-менеджеры. Платный агрегатор Metricool выкинут (18.06) — строим свои коннекторы.
- tests/       — эталонные задачи для проверки агентов
- docs/        — PLAN.md и документация
- .env         — ключи (токены ботов и пр.), НИКОГДА не коммитить (держим .env.example как образец)

## Репозитории и память — КУДА коммитить (детали: docs/ARCHITECTURE.md §6.0)
`/workspace` = 9p-маунт диска владельца (правки = его файлы сразу, без pull). ДВА репо:
- **Код** → `/workspace` = публичный `github.com/Kanaki-K/TG-Agents`. Правишь core/tests/docs/connectors → коммит СЮДА.
- **Память/крафт** → `/workspace/memory` = **ПРИВАТНЫЙ** `github.com/Kanaki-K/tg-agents-memory` (свой `.git` в memory/). Правишь `memory/*.md`/`*.json` (голос, эталоны, уроки, банки, мануалы — scope И флагман) → коммит в **memory-репо** (`git -C /workspace/memory ...`), НЕ в код.
- Рантайм читает память с **диска** (не с GitHub); git = только бэкап+история. Пуш обоих — владелец с Windows.
- ⚠️ origin памяти — ТОЛЬКО приватный; привязка к публичному TG-Agents сольёт IP. Проверка: `git -C /workspace/memory remote get-url origin` → tg-agents-memory. Мануал репо памяти: `memory/MEMORY_REPO.md`.

## Правила работы
- Объясняй понятным языком, что и зачем делаешь — владелец учится по ходу.
- Перед крупными изменениями сначала предложи план, потом выполняй.
- Секреты только в .env; никогда не пиши ключи в код или в файлы памяти.
- Идём от простого к сложному, по модулям (см. план сборки в PLAN.md).
- Каждое осмысленное изменение — отдельный git-коммит.
